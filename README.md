# 设备电量（Wireless Battery）v1.4

Windows 本地外设电量工具。支持 2.4G / 蓝牙双模，蓝牙阶梯电量带「上报值校验 + 时间推算」。
实测设备：MCHOSE A7 V2 Pro+、西伯利亚 K02BS、罗技 G PRO Wireless（经接收器）。

- 无第三方依赖，不联网
- 800×600 圆角扁平界面；关闭窗口默认隐藏到托盘
- 托盘按设备显示数字：鼠标绿色、耳机蓝色、低于 30% 红色
- 设备断开后保留最后一次电量，并显示「未连接」

## 主要功能

### 1. 双模识别

同一张卡片自动显示 `2.4G` / `蓝牙` / `双模`，右上角另有一个连接状态徽标：
**已连接**（黑字）/ **未连接**（灰字）。

- **MCHOSE A7 V2 Pro+**：Feature Report `0x11 / 0x06`，实测电量。
  启动时如果第一轮 HID 读取较慢或失败，会先显示上一次保存的电量卡片。
- **西伯利亚 K02BS**：2.4G 连接状态取自 Windows 音频端点；蓝牙电量取自 HFP 阶梯值
  （实测 80%，常见 0/20/40/60/80/100）。2.4G + 蓝牙同时存在时显示「双模」，使用蓝牙阶梯。
  判定口径见下文「K02BS 连接判定」。
- **2.4G 不做电量估算**：没有蓝牙电量时只显示最后一次读数 / 「等待蓝牙电量」。
- **罗技 HID++**：`0x1004` 百分比优先，`0x1001` 电压兜底（换算 + 滤波，见第 3 节）。

### 2. 蓝牙阶梯：自动校验 + 时间推算

K02BS（以及其他蓝牙设备）卡片右下角有：

- `阶梯估算` 开关：开关该设备的估算。
- `阶梯设置`：满电使用时间、阶梯档位（逗号分隔，如 `100,80,60,40,20,0`）、
  五段权重、恢复默认。权重按 `100-80、80-60、60-40、40-20、20-0` 五个区间逐行填写，
  每行右侧实时显示该段的**占比**（= 该段权重 ÷ 五项之和）与**预估时长**（= 占比 × 满电时间）。

规则：

1. **自动校验**：蓝牙上报值必须正好等于某个已配置阶梯。上报 `45` 而阶梯是
   `100,80,60,40,20,0` 时，卡片显示「阶梯估算设置有误」并说明原因。
2. **档内线性插值**：每档时长 = 该档在百分比轴上覆盖到的权重质量 ÷ 全阶梯权重质量 × 满电小时。
   权重为相对值（程序按总和归一化），因此五档时长之和恒等于满电小时数。
3. **主数字 = 时间推算值**，但夹在 `[下一档, 当前档]` 之间，不会掉到下一档以下；
   小字显示 `蓝牙反馈电量80% · 已保持2.5小时`。
4. 上报值跳到新档位时重新计时；权重不参与「计时锚点」签名，改权重不会重置已保持时间。
5. K02BS 进入「仅蓝牙」模式后不再补读，也不再把无反馈判为未连接，只冻结「已保持」时间；
   重新进入「双模」3 秒后补读一次，档位未变则从冻结处继续。

### 3. 罗技电压（HID++ 0x1001）

接收器支持两种路径：百分比特征（`0x1004`）或电压特征（`0x1001`）。电压路径的处理：

- 内置归一化锂电曲线（10 点分段线性）把电压映射成百分比，满/空锚点只做线性缩放，
  中段偏移按三角权重最多 ±10%；
- **中值滤波（窗口 1~7）→ EMA（α 0.1~0.5）→ 滞回死区 → 连续两次偏离才刷新**，
  放电态只降不升（回升需超过容差并连续 2 次站稳）；
- 插线（外部供电）时暂停换算，主数字显示「充电中」；低于 3000 mV 直接按 0% 并标「电压异常」；
- 卡片可打开「电压设置」调锚点与滤波参数；另有「观测最高电压」用于提示锚点是否偏高。

此外后台有一个只读监听线程接收设备主动推送的 `0x1001` 通知：命中时本轮一个请求都不发，
并据此判断「接收器在线、设备休眠」，避免把休眠误报成断开。

### 4. 断开保留最后电量

- 物理链路消失后先进入「连接波动」：10.5 秒后自动重试；连续 2 次漏拍且距首次断开
  ≥ 90 秒，才正式标记「未连接」。
- 标记未连接后仍保留最后一次电量，托盘 tooltip 加「（未连接）」；重新读到即恢复。

### 5. 勾选门控

设置里的「设备」列表按**已发现的型号**动态生成，勾选即为启用：

- 未勾选：不读电量、不查状态、不开句柄、不跑阶梯、不出卡片、不出托盘图标；
- 取消勾选时暂停阶梯计时，重新勾选从暂停处继续；
- 设置保存后立即生效，不需要重启。

### 6. 托盘

- 一个主图标（显示第一台有电量设备的数字）+ 每台设备一个数字图标。
- 鼠标绿色、耳机蓝色、**电量 < 30% 红色**；阶梯设置有误的设备图标变琥珀色。
- 双击打开主界面；右键可刷新 / 设置 / 退出；关闭窗口默认只隐藏。
- Windows 11 默认把新图标放进 `^` 溢出区，点 `^` 展开，或到
  「设置 → 个性化 → 任务栏 → 其他系统托盘图标」里打开「设备电量」。

#### 如果托盘一直显示「需要管理员权限」

这是权限倒挂：**Explorer 以管理员（High）运行，而程序是普通（Medium）权限**，
UIPI 会阻止 Medium 程序注册 `Shell_NotifyIcon`。任选一种处理：

1. 运行 `以管理员身份运行.bat`（结束旧实例后以管理员重启）；
2. 右键 `WirelessBattery.exe` → 「以管理员身份运行」；
3. 退出后重新启动——程序检测到托盘失败且当前用户可提权时会主动申请 UAC。

### 7. 单实例与启动

- 同一用户会话内只允许一个实例（命名互斥）。第二次启动会把「显示窗口 / 打开设置」的意图
  转发给已有实例然后退出，**不靠窗口标题找窗口**。
- 互斥创建失败（权限异常）不会崩溃，只在状态栏提示「未启用单实例保护」。
- 启动先用上次保存的电量画出卡片，首轮读取完成后再原地刷新。

### 8. 自动启动（默认开启）

优先级：**任务计划程序（HighestAvailable，登录延迟 3 秒，直调 `WirelessBattery.exe --tray`）**
→ 启动文件夹快捷方式 → 隐藏 `.vbs` → `HKCU\...\Run`。

每次启动会在后台核对现有入口是否仍指向当前 exe，不匹配就按上述顺序静默重写
（先建新、成功后清旧，不留空窗），结论写到状态栏一行：
`自启正常（计划任务）` / `自启已修复（计划任务）` / `未开启开机自启` 等。
因此**移动 exe 后不需要手动重新勾选**。

### 9. SmartScreen

未签名的 exe 无法保证 100% 不提示。已做：

- `app.manifest`：`asInvoker`、Windows 10/11 兼容、DPI 感知；
- 版本信息、多尺寸图标；
- `启动（无警告）.lnk` / `bin/打开设备电量.lnk`：快捷方式指向系统 `cmd.exe`，
  由 `启动设备电量.cmd` 先 `Unblock-File` 再 `start`，不对带「网络来源」标记的 exe 直接 ShellExecute；
- 计划任务直调 exe（不经资源管理器，因此登录启动不会弹 SmartScreen；也不经 cmd，
  避免 `cmd / start` 的令牌降级）。

彻底消除需要代码签名证书（EV 最好）。

## 支持情况

| 设备 | 状态 | 电量来源 |
|---|---|---|
| **MCHOSE A7 V2 Pro+**（`3837:100A`） | 实测 | Feature `0x11 / 0x06` |
| MCHOSE A7 V2 / A7 / AX5 / L7 / M7 | 理论可用 | 同一套 Classic Feature 协议 |
| MCHOSE V2（A5 V3 / K7 V2 等） | 自动尝试 | `0x4D / 0x0900` |
| **西伯利亚 K02BS**（`10D6:4801`） | 双模 | 蓝牙 HFP 阶梯 + 校验/推算；2.4G 只做连接状态 |
| **罗技 G PRO Wireless**（接收器 `046D:C539`） | 实测 | HID++ `0x1004` 百分比 / `0x1001` 电压 |
| 标准 HID 电量设备 | 自动尝试 | `0x0006 / 0x0020` |
| 罗技 HID++ 2.0 其它型号 | 自动尝试 | `0x1004 / 0x1000`，电压兜底 `0x1001` |
| 杰理（Jieli）2.4G 耳机 | 自动尝试 | `0xFF02` TLV `0x01` |

### 识别口径（型号级）

设备识别与匹配只用型号级特征：`VID/PID`、接口类型、音频端点 formfactor、设备类别。
不使用实例路径、USB 端口号、Container ID、序列号、音频端点 ID。
因此换 USB 口、换电脑、换同型号个体都能命中同一套协议路径；
反过来，**同一台电脑上两台同型号设备只会显示一张卡**（型号级键的必然结果）。

### 协议探测缓存

首次遇到某型号跑一遍探测链，命中结果按型号键写入 `settings.ini` 的 `Probe.*`：

| 项 | 规则 |
|---|---|
| 成功缓存 | 长期有效，但 `bcdDevice` 指纹变化立即失效 |
| 未识别负缓存 | 30 分钟；单会话探测次数到顶后拉长到 6 小时 |
| 探测限速 | 同型号 30 秒内不重复探测，单会话最多 3 次 |
| 超时 | 只累计失败次数，**不写负缓存**（设备休眠 ≠ 不支持），保留 10 秒级快速重试 |
| 拔插 | 本轮没枚举到的型号会在扫描结束时清掉缓存，重新插入即重新探测 |

## 已知限制

### K02BS 连接判定（实测口径）

接收器插着时会暴露多个音频端点，它们的 `DeviceState` 行为**不一样**：

| 端点 | formfactor | DeviceState |
|---|---|---|
| 耳机（A2DP） | 3 | 随蓝牙链路在 `0x1` ↔ `0x8` 之间翻转 |
| 免提（HFP） | 5 | 同上（偶见 `0x80000008`，只看低 4 位） |
| 扬声器（2.4G） | 1 | **恒为 `0x1`**，耳机开关机都一样 |
| 麦克风 | 4 | **恒为 `0x1`** |

因此判定是分档的：

- `ff=3/5` 激活，或 Windows 蓝牙 HFP 已上报电量 → 蓝牙链路通；
- 存在任一 K02BS 端点 → 接收器在线；
- **只有接收器在线时不算「已连接」**（默认严格口径）：2.4G 链路不回报耳机状态，
  接收器插着不等于耳机在用。卡片显示「未确认 · 接收器在线」，并保留最后电量。
- 如果你只用 2.4G、从不开蓝牙，可在「设置」里勾选
  「K02BS 只插接收器、耳机未开机时，也显示为已连接（较宽松）」，恢复旧的显示方式。

耳机关机后，蓝牙端点会掉到 `0x8`、HFP 电量也会消失，卡片在 10 秒重叠窗口后转为未连接/未确认。

### 其它限制

1. **2.4G 链路本身没有任何状态回报**：HID `0xFF90` 恒返回 `AC F8`，开关机/充电都不变；
   接收器的 PCM 流也照常可打开。所以「耳机开机但只连 2.4G」这件事，程序无法证实，
   只能显示「未确认」。
2. **罗技本体 `046D:4079` 不读数**：它以 `HID VHF Driver` 形式枚举、`out=0`，
   承载不了 HID++ 请求-应答；电量只能经接收器 `046D:C539` 获取，纯蓝牙直连不支持。
3. **跨机拷 `settings.ini` 首轮可能显示「连接中」**：断连冗余的副作用，10 秒后转为正常态；
   跑两次 `--once` 即为稳定态。
4. **同型号多设备共用一张卡与一个显示名**：键是型号级的，重命名也按型号键。

## 编译与测试

```powershell
powershell -ExecutionPolicy Bypass -File build.ps1                        # 编译到 bin/
powershell -ExecutionPolicy Bypass -File build.ps1 -Version 1.4.1 -Clean  # 升版本并重编
powershell -ExecutionPolicy Bypass -File tests/run-tests.ps1              # 纯逻辑自检，应为 ALL PASS
```

需要 Windows 自带的 .NET Framework 4.x。`build.ps1` 会在 `bin/build-info.txt` 写下
版本、构建时间、git commit 与 exe 的 SHA256，便于确认「手上这个 exe 是哪次构建」。

## 隐私

不联网、不上传数据、不写行为日志。仅在两种显式场景落文件：

- `--once`：在 exe 同目录生成 `scan.txt`（调试用，含设备型号与读数）；
- 未捕获异常：在 exe 同目录追加 `crash.txt`（超过 64 KB 时先清空再写）。

`settings.ini` 含设备名与电量历史，属个人数据，不要随仓库提交（`.gitignore` 已排除）。
