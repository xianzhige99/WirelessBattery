## 二、运行机制梳理

### 2.1 启动链路（`Program.cs`）

```
Main
 ├─ SetProcessDPIAware + WinForms 初始化 + 全局异常 → 写 crash.txt
 ├─ --once ?  → RunOnce()：同步扫一遍，写 scan.txt，退出（不参与单实例）
 ├─ 命名互斥 WirelessBattery_SingleInstance_v2
 │    └─ 创建失败（权限倒挂）→ 不崩、不当作已有实例，状态栏提示"未启用单实例保护"
 │    └─ 已存在 → 用命名事件把 --settings / 显示窗口的意图转发给主实例，本进程退出
 ├─ 托盘探针 TrayProbe.Test(Shell_NotifyIcon)
 │    └─ 失败 + 当前用户能提权 → runas 重启（--elevated 防循环）
 ├─ KillOldInstances()：按进程名杀掉 WirelessBattery* / 无线设备电量
 ├─ EnsureLauncher()：重写 启动设备电量.cmd（Unblock-File 再 start）+ 生成 打开设备电量.lnk
 └─ Application.Run(new TrayContext(...))
```

设计上比较讲究的三点：
1. **单实例不用窗口标题找窗口**，改用一个显示事件 + 一个设置事件，跨进程只传"意图"。
2. **权限倒挂先探针再提权**：普通 Explorer 下不会弹 UAC，只有"Explorer 是 High、自己是 Medium、托盘注册失败"三条同时成立才提权。
3. **提权前先释放互斥锁**，取消 UAC 后重新抢锁，避免自己把自己锁在门外。

### 2.2 调度中心（`TrayContext.cs`）

- **常驻线程**：`WaitHandle.WaitAny` 同时等两个命名事件，收到后 `BeginInvoke` 回 UI 线程（不碰控件）。
- **启动即出图**：先用 `BuildCachedResult()` 把上次电量画成卡片，避免首轮 HID 读取慢导致空白窗口（只恢复"上次连着且 24h 内见过"的型号 + 两个固定型号）。
- **五个定时器**：
  | 定时器 | 周期 | 职责 |
  |---|---|---|
  | `_timer` | `IntervalSeconds`（≥30s，默认 60s） | 主刷新 |
  | `_recheckTimer` | 10.5s | 断连冗余期间快速重试 |
  | `_modeTimer` | 3s 左右 | K02BS 重进"双模"后的补读 |
  | `_trayRetry` | 1.5s × 20 次 | 托盘注册失败重试，仍失败则最小化到任务栏 |
  | `_cleanupTimer` | 4s 一次性 | 清理探针留在注册表里的僵尸托盘项 |
- **扫描不阻塞 UI**：`Refresh()` 用 `_busy` 去重，线程池跑 `BatteryService.Scan()`，结果回 UI 后先按勾选裁剪，再刷托盘和卡片。
- **自启审计**：每次启动在线程池里核对该入口是否仍指向当前 exe，不符则静默重写，结论只写状态栏一行。

### 2.3 扫描管线（`BatteryReader.cs` `Scan()`）—— 这是整个软件的核心

```
HidNative.Enumerate()            遍历全部 HID 接口（SetupAPI + hid.dll）
BluetoothBattery.Scan()          遍历蓝牙设备节点，读电量属性
        │
        ▼
按 VID:PID 分组 → HidGroup        「型号级」分组：同型号不同个体/端口合并成一台
        │                          （跳过 MCHOSE MagDock 0x3837:0x1012）
        ▼
DetectKind()                     3837→MCHOSE｜10D6:4801→K02BS｜3654/4C4A+FF02→杰理
                                 046D→罗技｜有电池 usage→通用 HID
        │
        ▼
勾选门控                         未勾选：不读、不查状态、不开句柄、不跑阶梯、不探测、不出卡
        │
        ▼
ReadGroup() 分派
 ├─ MCHOSE   → ReadMchoseRouted   缓存命中直读，未命中跑探测链（Feature 0x11/0x06 → V2 0x4D/0x0900）
 ├─ K02BS    → ReadK02BS          音频端点判 2.4G + 蓝牙 HFP 电量 + 阶梯校验/时间推算
 ├─ 罗技     → ReadLogitechRouted 0x1004 百分比 / 0x1001 电压→曲线换算+滤波；被动监听线程收推送
 ├─ 杰理     → JieliReader        FF02 TLV + CRC16
 └─ 通用     → GenericBatteryReader  HID Battery Strength usage
        │
        ▼
蓝牙设备单独成卡（键 BT:<名称>）→ 固定型号补位 → 首次发现型号才落盘
        │
        ▼
PendingDisconnect / RecheckAfterMs → EndScan 清理不在场型号缓存 → 启动罗技监听线程
```

### 2.4 协议路由缓存（`ProtocolRouter.cs`）

这是"每次刷新逐个试协议"到"首次探测、之后直读"的关键改造：

| 项 | 规则 |
|---|---|
| 缓存键 | 型号级：`3837_100A`、`046D_C539` |
| 成功缓存 | 3,650 天，但 `bcdDevice` 指纹变化立即失效 |
| 未识别负缓存 | 30 分钟；探测次数到顶后拉长到 6 小时 |
| 探测限速 | 同型号 30 秒内不重复探测；单会话最多 3 次 |
| 超时 | **不写负缓存**，只累计 `Fails`，保留 10s 级快速重试 |
| 严格判定 | 设备"明确回答没有电池特性"要连续 2 轮才写负缓存（避免冷启动误判） |
| 清理 | `EndScan()` 清掉本轮不在场的型号，插拔后会重新探测 |

这套规则里有一个很实在的取舍：**"超时不等于不支持"**——设备休眠时不该被打进 30 分钟黑名单。这类判断通常要在踩过坑之后才写得出来。

### 2.5 显示规则与状态机

- **卡片四段信息**：标题/副标题（VID·PID·类别）→ 模式徽标（2.4G/蓝牙/双模）+ 连接徽标（已连接/未连接）→ 大数字 → 小字（`蓝牙反馈电量40% · 已保持10小时`）+ 状态行 + 详情。
- **颜色**：<30% 红、阶梯设置有误琥珀、鼠标绿、耳机蓝。托盘图标同规则。
- **断开处理**：保留最后一次电量 + "未连接"；短时断连进"连接波动"，10.5s 后重试。
- **10 秒冗余的实际实现**：`UpdateLinkState()` 要求"连续 2 次漏拍 **且** 距首次断开 ≥ 90 秒"才正式判未连接（`AppSettings.cs:635`）。
  ⚠️ 这与 README/使用说明里写的"10 秒冗余"不一致——实际是"10.5s 重试 + 90s 确认"。

### 2.6 配置层（`ConfigStore.cs`）

`settings.ini` 155 行，五段前缀：

```
Interval / CloseToTray / AutoStartWanted        全局
Device.<key>.Enabled|Seen|ShowCard|ShowTray|Order|Name|LastSeen
Estimate.<key>.Enabled|Hours|Stages|Weights      阶梯估算
Runtime.<key>.…（20+ 字段）                       连接状态、阶梯锚点、冻结、模式
Probe.<型号>.Proto|Type|Feature|Ts|Until|Fails|Ver 协议路由缓存
Gpw.…                                            电压校准与观测
```

做得好的地方：
- **原子写**：先写 `.tmp` 再替换，失败不留半截文件；写锁串行化（UI 线程 + 后台线程都会写）。
- **键名白名单**：`IsSafeDeviceId()` 拒绝含 `\ / # { }`、`VID_`、`PID_`、`MI_` 的键——从写盘层堵死"实例级标识"。
- **旧配置无损**：缺 `ShowCard/ShowTray/Order` 时按启用状态补齐，老程序仍能读回。

需要警惕的地方：
- **写得太勤**：一次刷新里 `SetLastLevel`、`UpdateLinkState`、`EstimateBt`、`ApplyBtEstimate`（"双模"下**每轮必写**，`BatteryReader.cs:1048`）都会整文件重写。60s 间隔下约 1,400 次/天 × 155 行。

### 2.7 自启与 SmartScreen 链路

- 优先级：**计划任务（HighestAvailable，登录延迟 3s，直调 `exe --tray`）** → 启动文件夹快捷方式 → 隐藏 VBS → `HKCU\...\Run`。
- 每次启动后台审计"入口是否存在且指向当前 exe"，不符则按上述顺序静默重写（"先建新、成功后清旧"，避免空窗）。
- 免 SmartScreen：启动脚本先 `Unblock-File` 再 `cmd /c start`；快捷方式指向 `cmd.exe` 而非 exe。

## 四、问题清单（按"该不该现在动手"分级）

### P0 · 工程护栏缺失（影响每一次后续改动）

**P0-1 没有版本控制，改坏了回不去**
- 证据：包内无 `.git`；`dist/`（10-27 01:32，277KB）与 `bin/`（10-30，282KB）两套 exe 并存且不同步；交接记录里 8 个任务段的改动只能从会话日志里翻。
- 影响：任何一次"改 A 顺手动了 B"都无法回滚；无法回答"这行为是哪次改的"。
- 建议：`git init` + 首次提交打 `v1.3-baseline` 标签；此后一个任务一个分支、一次提交，提交信息写"块N 优化M：一句话"。
- 验收：`git log --oneline` 能串起 8 个任务；`git checkout v1.3-baseline` 能回到今天的状态。

**P0-2 版本号与产物脱节**
- 证据：`AssemblyInfo.cs` = 1.3.0.0；README/使用说明 = v1.3；实际功能已到"1.4"级别（单实例、路由缓存、勾选门控、权重曲线、GPW 电压、配置层、重命名、被动监听）。
- 建议：升 1.4.0.0；`build.ps1` 接受 `-Version` 参数注入；`bin/` 只保留一份产物，删除 `dist/`（或改为 `build.ps1 -Pack` 生成的 zip）。
- 验收：exe 属性页版本 = README 标题版本 = `CHANGELOG.md` 最新条目。

**P0-3 仓库里混入无关文件与个人数据**
- 证据：`.tmp/backup/{package.json,pnpm-lock.yaml,cordis.patch.yml,pnpm-workspace.yaml}`（另一个 node 项目的残留）、`debug.log`（搜狗输入法日志）、`bin/settings.ini`（含真实设备名 `XIBERIA K02BS`、时间戳、电量）、`bin/scan.txt`。
- 影响：仓库体积、隐私、误导后来者（会以为项目有 node 依赖）。
- 建议：删除上述文件；`.gitignore` 增补 `settings.ini`、`scan.txt`、`crash.txt`、`bin/*.exe`（若不打算提交二进制）、`.tmp/`、`dist/`；提供 `settings.example.ini`。
- 验收：`git status` 干净；克隆后无 `settings.ini` 也能 `build.ps1` 通过并正常启动。

**P0-4 文档与代码已出现 4 处实质性漂移**
| # | 文档说法 | 代码实际 | 位置 |
|---|---|---|---|
| 1 | 计划任务"调用同一个 .cmd" | 直调 `exe --tray`（有意为之：避免 cmd 令牌降级） | `AppSettings.cs:1116` |
| 2 | K02BS 只认 `formfactor=3/5` 端点 | 认**任何**描述含 K02BS 且 `DeviceState&0x0F==1` 的端点，formfactor 仅用于排序 | `AudioLink.cs:59` |
| 3 | 断连冗余"10 秒" | 10.5s 重试 + **2 次漏拍且 ≥90 秒**才判未连接 | `AppSettings.cs:635` |
| 4 | "不写日志" | 写 `crash.txt`（无大小上限、无限追加） | `Program.cs:218` |

- 建议：一次对账，以代码为准改文档；把"文档同步"写进任务完成的 Definition of Done。
- 验收：README 每条机制描述都能指到具体函数。

**P0-5 没有可重复的回归验证**
- 证据：历史上有过 `probe1..probe18.cs` 形式的断言程序，但都是一次性临时文件，没进仓库；现在唯一的验证手段是 `build.ps1` + 手工 `--once`。
- 建议：把探针沉淀为 `tests/SelfTest.cs`（同一份 csc 就能编译运行），覆盖纯逻辑：阶梯段时长、电压映射与滤波、ini 往返、`IsSafeDeviceId`、`EstimateBt` 边界。
- 验收：`powershell -File tests/run-tests.ps1` 输出 `ALL PASS`，不改硬件即可跑。

### P1 · 运行时行为（有实际风险，改动小）

**P1-1 启动时按进程名强杀同名进程**
- 证据：`Program.cs:191 KillOldInstances()`，匹配 `WirelessBattery*` / `无线设备电量`，直接 `p.Kill()`。
- 风险：会误杀用户另存的调试副本/旧版本；与"不得粗暴终止进程"的约束冲突；而单实例互斥（v2）本身已能防多开，这个函数是历史遗留的补丁。
- 建议：收敛为"只结束指向同一 exe 路径的旧实例"，或只针对旧 mutex 名（v1）做一次性迁移清理，之后删除。

**P1-2 托盘图标 GDI 句柄只增不减**
- 证据：`TrayManager.cs:133-139`，每次换图标 `bmp.GetHicon()` 后把句柄 Append 到 `_handles`，只在 `Dispose()` 统一销毁。
- 影响：长跑（尤其 K02BS 阶梯推算值每轮变化）会持续累积 HICON。
- 建议：换图标时立刻 `DestroyIcon` 旧句柄（`NotifyIcon` 已复制图标），`_handles` 只保留当前一个。
- 验收：挂机 24h 后进程 GDI 对象数不增长（任务管理器"GDI 对象"列）。

**P1-3 `settings.ini` 每轮整文件重写**
- 证据：`BatteryReader.cs` 内 6 处 `Settings.Save()`，其中 `:1048` 在 K02BS"双模"下**每轮刷新必写**。
- 影响：SSD 无所谓，但放大了"写一半被杀"的窗口，也让"配置是否被程序改动"这类排查变难。
- 建议：脏标记 + 合并写（最多 30s 一次）+ 退出时 flush；`Runtime.*` 可考虑拆到 `runtime.ini`。

**P1-4 `Control Panel\NotifyIconSettings` 有写入动作**
- 证据：`TrayProbe.CleanupStale()` 会删除 tip 为"设备电量"且 UID=0x5A5A 的子键。
- 风险：属于用户级托盘偏好设置，误判会重置"始终显示"选择。
- 建议：限定只删自己探针写过的键（tip 用唯一串 `设备电量托盘检测`），并加一次开关（默认开）。

**P1-5 单实例事件没有 ACL 设计**
- 证据：`EventWaitHandle` 用默认 ACL；提权实例（High）与普通实例（Medium）跨完整性级别互相 `Set()` 未做显式授权。
- 风险：提权后"双击图标再启动一次"可能无法唤起已运行实例（静默失败）。
- 建议：启动时若 `SignalEvent` 全部失败，退回"托盘气泡提示已在运行"或短暂显示错误，而不是静默退出；正式修法是在创建事件时传 `EventWaitHandleSecurity`。

### P2 · 使用与体验（锦上添花）

| 编号 | 问题 | 建议 |
|---|---|---|
| P2-1 | 首次使用要读完 README 才知道点哪个 lnk/bat；SmartScreen、托盘 `^` 溢出、管理员权限三件事各有说明 | 首次运行 3 步向导：解除锁定 → 开自启 → "把托盘图标拖出 `^`"图示；主界面首启横幅 + 一键"修复托盘" |
| P2-2 | 设置分散：全局设置在窗口里，阶梯/电压/重命名在卡片链接上 | 设置窗口加"设备"页签收拢这三项，卡片入口保留 |
| P2-3 | 只有当前值，没有趋势 | 内存保留最近 N 次读数（可选 CSV），画 24h 折线——用来证明"阶梯估算准不准"最直观 |
| P2-4 | <30% 只变红，无提醒 | 20% / 10% 各一次托盘气泡，带静默期与"本次开机不再提醒" |
| P2-5 | 状态栏文案会经历"读取中 → 已连接"，跨机拷配置首轮可能显示"连接中" | 卡片加"数据时间"（`12 秒前`），缓存值与实时值用不同灰度区分 |
| P2-6 | 同型号两台只有一张卡（型号级键的必然结果） | 文档显式声明这是设计取舍；重命名也按型号键，两台共享名字 |
| P2-7 | 固定 800×600 + 手写像素布局 | 25 寸 4K / 150% 缩放下检查一遍；必要时 `AutoScaleMode.Dpi` |

### 已知限制（不是 bug，是物理/系统限制，建议写进 README）

1. **K02BS 2.4G 关机后可能仍显示"已连接"**：真机抓过 ON/OFF 两态，音频端点 `DeviceState` 完全一致（`Render state=1 ff=1` / `Capture state=1 ff=4`），HID `0xFF90` 恒返回 `AC F8`。目前没有可靠的软件判据——已按你的决定"搁置"。
2. **GPW 本体 `046D:4079` 不读数**：以 `HID VHF Driver` 形式枚举、`out=0`，承载不了 HID++ 请求-应答，只能经接收器 `C539` 取。
3. **跨机拷 `settings.ini` 首轮可能"连接中"**：这是断连冗余的副作用，跑两次即稳定。

## 五、项目管理调整建议

### 5.1 仓库结构（建议目标形态）

```
WirelessBattery/
├─ src/                     源码（按职责再拆子目录）
│   ├─ readers/             MchoseReader / LogitechReader / JieliReader / ActionsReader / GenericReader
│   ├─ settings/            RuntimeState / Estimate / AutoStart 三个 partial
│   └─ ui/
├─ tests/                   SelfTest.cs + run-tests.ps1
├─ docs/
│   ├─ 01-现状梳理与优化建议.md   ← 本文
│   ├─ 02-决策记录.md            ← 硬约束 + 每次拍板（D1A/D2A …）的理由
│   ├─ 03-回归清单.md            ← 5 条固定回归
│   └─ 04-协议笔记.md            ← 各设备实测报文（这是最贵的资产）
├─ tools/                   make-icon.ps1、pack.ps1
├─ assets/、bin/（产物，不入库）
├─ build.ps1  CHANGELOG.md  README.md  使用说明.txt
└─ .gitignore
```

**为什么值得拆 `BatteryReader.cs`**：它现在同时承担"枚举/分组/门控/路由/五类设备读取/卡片状态机"六件事，2,055 行里一个 `ApplyMeasured` 就有 140 行。建议在**独立提交、零功能变更**的前提下按 `readers/` 拆，让每次改协议只碰一个文件。

### 5.2 任务流程模板（把现有好习惯固化下来）

你现在的流程其实很有效：**硬约束块 → 基线核对 → 计划 → 拍板 → 实施 → 报告（改动/回滚/验证）**。建议把它落成 `docs/任务模板.md`，换任何模型/人接手都一样：

```
## 任务：块N 优化M（名称）
### 硬约束          （13 条原文，每次必带）
### 现状基线         代码实测 + 与我的认知差异
### 计划             改哪些文件 / 意图 / 风险 / 验收 / 回滚（不贴代码）
### 待拍板项         D1/D2…（给选项 + 推荐 + 理由）
### 实施与验证       build OK + 回归清单 + 相关自检项
### 交付            改动清单 / 回滚方式 / 未覆盖风险 / 手动验证步骤
```

建议新增两条纪律：
1. **"文档同步"是完成条件**：代码与 README/使用说明/验收文档不一致，视为任务未完成。
2. **"验证脚本入库"是完成条件**：临时探针要么删掉，要么进 `tests/`——不接受"只存在于会话里"。

### 5.3 版本与发布

- 语义化版本：`1.4.0`（本轮 8 个功能）→ 之后 `1.4.x` 修 bug、`1.5.0` 加功能。
- `CHANGELOG.md` 按"新增 / 修复 / 变更 / 已知限制"四段写；交接记录里 8 个任务段直接就是 release note 素材。
- 发布产物：`build.ps1 -Pack` 生成 `WirelessBattery-1.4.0.zip`，内含 exe（两个名字）+ 三个 bat/lnk + `settings.example.ini` + `使用说明.txt`；zip 内附 `build-info.txt`（版本、构建时间、源码 commit、exe SHA256）。

### 5.4 回归清单（每次改完必跑，5 条）

1. `build.ps1` → `Build OK`、exit 0。
2. 三款设备全部唤醒 → `--once` 出 3 张卡且 `connected=True`。
3. 主界面托盘数字与卡片数字一致；<30% 变红；断开 10s 后仍显示最后电量 + "未连接"。
4. 状态栏出现自启审计结论（`自启正常（计划任务）` 或 `自启已修复（…）`）。
5. `settings.ini` 里不出现 `\\?\`、`HID#`、`BTHENUM\`、`USB\VID_`、`&` 等实例级特征；跑 `--once` 前后 SHA256 一致（除非首次发现新型号）。

### 5.5 交接资产瘦身

现在的交接包是 **650KB 压缩视图 + 20MB 会话日志**，可读性差且大量是过程噪音。建议改为：

```
交接包 = 仓库（含 docs/01~04） + 当前 exe + 本次任务清单
附录   = 会话日志（仅当需要追溯某个决定的原话时再查）
```

真正需要传下去的是 **`docs/02-决策记录.md`**：为什么"超时不写负缓存"、为什么"型号级键导致同型号只出一张卡"、为什么"计划任务直调 exe"。这些理由比代码本身更难重建。

## 七、值得保留的东西（重构时别丢）

- **型号级识别纪律**：VID/PID + 接口类型 + formfactor + 类别，不碰实例路径/端口/序号/Container ID。这条让"换电脑、换接口、换个体"都能复现。
- **"超时不写负缓存"**：区分"设备说没有"和"设备没说话"，避免休眠把型号打进黑名单。
- **探测限速 + 固件指纹失效**：既省发包，又能在刷固件后自动重新探测。
- **配置原子写 + 键名白名单**：从写盘层堵死实例级键，比在业务层做检查可靠得多。
- **交付口径**：每个任务都要求"技术基线核对 + 计划先批 + 改动清单 + 回滚方式"。这套纪律比代码值钱。
