# 交接说明（换电脑 / 换会话接手先看这里）

> 目标：任何一台 Windows 上，5 分钟内恢复到"能编译、能验证、知道该改哪"的状态。

## 1. 现状一句话

Windows 外设电量托盘工具，C# 5 / .NET Framework 4.x / WinForms，**零第三方依赖**、不联网、单 exe 绿色版。

| 项 | 值 |
|---|---|
| 当前版本 | **1.4.4**（`src/AssemblyInfo.cs` 是唯一真源） |
| 编译 | `build.ps1` 通过 |
| 自检 | `tests\run-tests.ps1` → `PASS 124  FAIL 0  ALL PASS`（纯逻辑，不碰硬件） |
| 项目路径 | `C:\Users\XZ\WorkBuddy\MyWorks\WirelessBattery` |
| 交付副本 | `MyWorks\software\WirelessBattery\`（WirelessBattery.exe + GpwBatteryProbe.exe） |
| 远端仓库 | https://github.com/xianzhige99/WirelessBattery —— **停在 1.4.0，1.4.1+ 未推送** |

实测设备：罗技 G PRO Wireless（经 LIGHTSPEED 接收器，PID `0x4079`）、MCHOSE A7 V2 Pro+、西伯利亚 K02BS。

## 2. 环境与三条命令

只用系统自带的东西，不需要装 SDK：

```
build.ps1 -Clean -Strict         → Build OK
tests\run-tests.ps1              → ALL PASS（124 项断言）
bin\WirelessBattery.exe --once   → 生成 scan.txt 看设备识别结果，不开界面
```

其它开关：`--tray` / `--minimized` 启动即隐藏，`--settings` 直接开设置页，`--elevated` 内部提权重启用。

## 4. 1.4.1 ~ 1.4.4 做了什么

| 版本 | 内容 |
|---|---|
| 1.4.1 | GPW 电量改用**设备级曲线**（与 G HUB 网页版同源 `battery.xml`）；充电时数字按充电曲线/时间表继续推进；新增 `ReadModelId` 读 HID++ `0x0003` |
| 1.4.2 | 托盘图标换成**七段数码管字形**（90° 尖角端、1px 尖角间隙）；`FC` 触发 ≥99%；多尺寸 ICO（16/20/24/32）；主程序图标固定用软件图标 |
| 1.4.3 | 修「充电中显示未知灰」：配色改为**充电优先**；被动推送帧解析充电位；被动路径补读 PID；充电无基准时不再从 0% 编数字 |
| 1.4.4 | 修「设 5/10 分钟却仍 30 秒刷新」：删掉充电时强制 30 秒的逻辑；状态栏增加「每 X 刷新」 |

托盘配色：鼠标绿 `#22C55E`、耳机蓝 `#3B82F6`、电量 <30% 红 `#F04438`、充电中黄 `#FACC15`、`FC` 跟随设备默认色、未知灰 `#98A2B3`。

## 5. 踩过的坑（别重复踩）

1. **GPW 的 PID 不在规范位**：`0x0003` 应答里 `0x9490` 是假 PID，真 PID `0x4079` 在 capabilities 之后。现在的做法是"整段载荷里找能对上曲线表的 ID"。
2. **充电状态位**：被动推送帧 `f[6] & 0x80` = 充电中。状态翻转时会写日志「设备推送电压帧 … 状态位 … 判定 …」，排查插电不黄就看这行。
3. **充电没基准就不给数字**：平台区（≥4100 mV）电压没有信息量，充电时间表必须从已知起点累加，所以"插着电启动"必然显示 `—` + 黄色充电中——这是刻意行为，不是 bug。
4. **曲线表是生成的**：现有 6 型号、按 0.4 个百分点误差抽稀（GPW 707→46 点）。改算法只改 `tools/gen-battery-curve.py`，别手改生成物。
5. **G903 的 PID**：旧文档写 `0x4053`，G HUB 现在用 `0x4067`；表里是 `0x4067`。
6. **刷新间隔**：只由设置决定，不要再按充电状态插一脚（1.4.4 就是为这个改的）。
7. **`bin\settings.ini` 目前不存在**：恢复项目时没带过来，首次运行按默认值生成，设备勾选与灵敏度要重设一次。

## 6. 已知限制（不要当 bug 反复查）

1. **K02BS 只连 2.4G 时显示「未确认」**：2.4G 链路不回报耳机状态，接收器也不给（`0xFF90` 恒 `AC F8`），是刻意取舍（D13/D16）。
2. **罗技本体 `046D:4079` 直连读不到**：`HID VHF Driver`、`out=0`，只能经接收器取。
3. **同型号多设备共用一张卡**：卡片键是型号级的（D1/D2）。
4. **16px 托盘图标**：两位数（如 `24`）偏糊，属分辨率物理极限；`FC`、`75` 清楚。

## 7. 本工作区的文件治理规则（必须遵守）

规则真源：`MyWorks\.workbuddy\memory\MEMORY.md`。对本项目的落点：

| 规则 | 落地做法 |
|---|---|
| R1 归属 | 所有产出只在 `MyWorks\` 内；区外只读 |
| R2 结构 | 工作区根只允许 `_shared/ backup/ software/ <项目>/` |
| R3 命名 | 新文件 ASCII + 下划线，不带"最终/副本"；交付成品可带 `vX.Y.Z` |
| R4 交付 | 成品放 `software\WirelessBattery\`，覆盖旧副本、只留最新一份 |
| R5 备份 | 覆盖源码/配置前备份到 `backup\WirelessBattery_backup\<时间戳>\`，留最近 5 份 |
| R6 临时 | 构建日志放项目 `tmp\`，任务收尾清空 |
| R10/R11 | 区外改动、3 个以上文件的整理，先出清单再动手 |
| R12 删除 | 走回收站；永久删除需二次确认 |
| R13 记忆 | 项目结论写本目录 `docs/`，不往工作区记忆里塞 |

## 9. 出问题怎么退

- **代码改坏**：`backup\WirelessBattery_backup\<时间戳>\` 里有覆盖前的原文件，取最近一份。
- **数据表坏了**：`py -3 tools/gen-battery-curve.py` 重新生成，不依赖本地缓存。
- **图标不对**：先跑 `tools\design-tray.ps1` 看样式稿，再跑 `tools\preview-icons.ps1` 看真实渲染，两者必须一致。
- **要 1.4.0 基线**：`Downloads` 那个 zip 是完整快照（含 `.git`）。
