# 三款设备识别验收（块 8）

本文件是验收口径与操作清单，供在任何一台电脑上重复执行。判读一律以 `--once` 生成的 `scan.txt` 为依据，不靠界面截图、不靠猜测。

## 一、验收口径（已定）

| 设备 | 稳定标识（只允许型号级） | 协议路径 | 通过标准 |
|---|---|---|---|
| MCHOSE A7 V2 Pro+ | `VID=0x3837`（不看 PID、不看端口） | Feature `0x11` / `0x06`（失败再试 V2 帧） | 卡片出现、`connected=True`、电量非 `—` |
| 西伯利亚 K02BS | `VID=0x10D6` + `PID=0x4801` | 音频端点 formfactor=3/5 + `DeviceState&0x0F==1` 判连接；HID `0xFF90`（Actions）+ 蓝牙电量 + 阶梯推算 | `connected=True`；启用估算时 `estimated=True` 且显示「蓝牙反馈电量 X% · 已保持 Y 小时」 |
| 罗技 GPW | 接收器 `046D:C539`（本体 `046D:4079` 仅要求出现在枚举里） | HID++ 2.0：`0x1004`/`0x1000` 百分比优先，`0x1001` 电压兜底 | `connected=True`；状态为「电压估算」（或插线时「充电中」），`hint` 含「观测最高 X mV · 样本 N」 |

两条已拍板的边界，不算缺陷：

1. **GPW 本体 `046D:4079` 不读数**。它以 `HID VHF Driver` 形式枚举，接口 `out=0`，无法承载 HID++ 请求-应答。电量只能通过接收器 `046D:C539`（鼠标唤醒、ping 应答）获取；纯蓝牙直连场景不支持读数。
2. **跨机配置首轮可能显示「连接中」**。把 `settings.ini` 从电脑 A 拷到电脑 B 后，K02BS 可能先显示 `连接中 · 连接中断 · 10秒内自动重试`，10 秒后转 `未连接 · 最后电量`。这是块 1 要求保留的断连冗余，可用「跑两次 `--once`」消除：第二次即稳定态。

## 二、操作步骤（每台电脑各做一遍）

1. 插好三个接收器（A7、K02BS、GPW），并分别唤醒设备：A7 动一下、K02BS 开机、GPW 动一下。
2. 在 `bin` 目录执行：`.\无线设备电量.exe --once`
3. 打开同目录 `scan.txt`，按下表逐行判读。
4. 换一个 USB 端口重做步骤 2、3，判读结果必须逐字不变。

## 三、`scan.txt` 判读

文件结构：`SCAN`（时间）、`INTERFACES`（枚举到的 HID 接口数）、`CARDS`（卡片数）、逐行 `CARD …`、`BT`、`LOG`（诊断原因）。

| 设备 | 通过时的特征 | 失败时的分支 |
|---|---|---|
| A7 V2 Pro+ | `CARD MCHOSE A7 V2 Pro+`，`connected=True`，电量非 `—`；LOG 无「未发现设备」 | 枚举里没有 `3837:100A` → 接收器/线/端口；有枚举但 `connected=False` → 鼠标休眠，唤醒后重跑 |
| K02BS | `CARD 西伯利亚 K02BS`，`connected=True`；估算开启时 `estimated=True`，`hint=蓝牙反馈电量 X% · 已保持 Y 小时` | LOG 出现「没有找到 K02BS 的耳机音频端点」→ 耳机没开机（接收器插着也不算连接，属设计路径） |
| GPW | `CARD USB Receiver`，`connected=True`，状态含「电压估算」/「充电中」，`hint` 含「观测最高」 | LOG 出现「轻量 ping 未应答」→ 鼠标深度休眠；只有 `046D:4079`、无 `C539` → 接收器未插（按边界 1 不支持读数） |

其它需要留意的字段：

- `invalid=True` + 「阶梯设置有误」：蓝牙上报值不在阶梯列表里，属配置问题，不是识别失败。
- `est…`/`estimated=True`：表示主数字来自时间推算；`False` 表示实测值。
- `LOG` 里的「探测间隔未到」「探测次数已达上限」：块 3 的探测限速，说明该型号此前探测未成功，等下一轮或重新插拔设备。

## 四、交叉检查

1. **同型号两台**：分别插在电脑 A、电脑 B，各自出卡、电量互不影响。注意**同一台电脑上两台同型号只会有一张卡**——设备键是型号级的，这是块 3 硬要求的必然结果。
2. **换端口**：任一设备换 USB 口后重跑，`scan.txt` 判读不变（实现不读端口号、实例路径、Container ID、序列号）。
3. **配置迁移**：把 A 机 `settings.ini` 拷到 B 机 → 连续跑两次 `--once` → 第二次应为 `未连接 · 最后电量`；`settings.ini` 中出现 `Probe.<型号>.Proto=…` 即表示协议路由缓存已按型号级键复用。

## 五、本机留档（2026-10-27 01:26，Windows 10/11 x64）

- 枚举 20 个 HID 接口，其中：`10D6:4801` ×4（含 `0xFF90` in/out 各 64、`0xFF82`、`0x000B`、`0x000C`）、`046D:C539` ×6（含三个 `0xFF00` 厂商页，out 长度 32/7/20）、`046D:4079` ×1（`usagePage=0x0059`、`in=2`、`out=0`、`feat=51`、产品名 `HID VHF Driver`）、`046D:C232` ×1（键盘），**无 `3837:100A`**。
- 当时 K02BS 耳机未开机、GPW 鼠标休眠、A7 未上电，因此 `scan.txt` 为 3 张「未连接 + 最后电量」卡，属设备侧状态，不是识别失败。
- `settings.ini` 中 `Probe.10D6_4801.Proto=HidActions / Type=Percentage / Ver=4866`（bcdDevice 0x1302），证明探测缓存按型号级键落盘。
- `--once` 运行前后 `settings.ini` SHA256 一致（3075 字节），说明该模式不会无故改写配置。

## 六、回归检查（以后改协议/路由时用）

1. 改完必须 `build.ps1` 编译通过（`Build OK`、exit 0）。
2. `--once` 在「三款设备全部唤醒」的环境下应出 3 张卡且 `connected=True`。
3. `settings.ini` 里不允许出现 `\\?\`、`HID#`、`BTHENUM\`、`USB\VID_`、`&` 等实例级特征（块 7 已在写盘层拒绝）。
4. 换端口、换电脑、换同型号个体后，`Probe.*` 缓存仍然命中，不得重新回到「每轮全量探测」。
