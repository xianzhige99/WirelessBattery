# 回归清单

每次改完代码按顺序跑一遍，全绿才算完成。前两项不需要硬件，后四项需要真机。

## 1. 编译（无硬件）

```powershell
powershell -ExecutionPolicy Bypass -File build.ps1 -Clean -Strict
```

期望：`Build OK`，exit 0，且没有警告（`-Strict` = `/warnaserror`）。
同时确认 `bin/build-info.txt` 的 version / commit 与预期一致。

## 2. 纯逻辑自检（无硬件）

```powershell
powershell -ExecutionPolicy Bypass -File tests/run-tests.ps1
```

期望：末行 `ALL PASS`，exit 0，`FAIL 0`。
覆盖：阶梯段时长与权重、阶梯校验、电压→百分比曲线、滤波（充电/异常/只降不升）、
配置往返（含 `Probe.*`）、型号级键白名单、设备名清洗。

## 3. 集成冒烟（需要设备）

1. 三款设备全部唤醒（鼠标动一下、耳机开机、GPW 唤醒）。
2. 在 `bin` 目录执行 `.\WirelessBattery.exe --once`。
3. 打开 `scan.txt`：`CARDS` 应为 3，三条 `CARD` 均 `connected=True`，
   MCHOSE 与 GPW 有电量或「电压估算」，K02BS 的 `hint` 含「蓝牙反馈电量」。
4. 再跑一次，结果应稳定（第二次不再出现「连接中」）。

## 4. 界面与托盘（需要设备）

- 主界面卡片数字与托盘图标数字一致；<30% 变红；阶梯设置有误变琥珀。
- 关闭窗口 → 隐藏到托盘且程序不退出；托盘右键「退出」能真正结束进程。
- 断开设备 → 先「连接波动」，90 秒后转「未连接」并保留最后电量。
- 设置里取消勾选某设备 → 卡片与托盘图标立即消失；重新勾选 → 恢复且阶梯计时从暂停处继续。

## 5. 单实例与自启（需要一次登录）

- 双击两次只出现一个窗口、一套托盘图标；带 `--settings` 第二次启动应直接打开设置页。
- 状态栏出现自启审计结论（`自启正常（计划任务）` / `自启已修复（计划任务）` 等）。
- 把 exe 挪到别的目录后启动一次 → 状态栏显示「自启已修复」，重启登录仍能自启。

## 6. 配置健康度（需要设备）

- `settings.ini` 中不出现 `\\?\`、`HID#`、`BTHENUM\`、`USB\VID_`、`&` 等实例级特征。
- 确认没有残留 `settings.ini.tmp`。
- 观察 10 分钟：进程「GDI 对象」数不应持续增长；`settings.ini` 的修改时间应是约 20 秒一次的合并写，
 而不是每轮刷新都变。

## 失败处理

- 编译失败：先看 csc 报的第一条错误，不要边猜边改。
- 自检失败：先判断是**测试预期错了**还是**代码错了**——两项都记在 `docs/02-决策记录.md` 的设计里。
- 真机失败：用 `--once` 的 `scan.txt` 定位（它有枚举清单、卡片字段和 LOG），不要靠截图猜。
